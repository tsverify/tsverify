## 2. Dependency rules (enforced by review; a lint rule later)

```
                 ┌──────────────────────── cli ───────────────────────┐
                 │                                                    │
     spec   checker   render   extractor   conformance   testgen   viewer
       │       │        │          │            │           │        │
       └───────┴────────┴──────────┴─────┬──────┴───────────┘        │
                                         ▼                           │
                                        ir  ◀────────────────────────┘ (viewer → ir, render)

     runtime   (no internal deps: imported by *generated tests* in user projects)
```

1. **`ir` depends on nothing internal.** Every shared type lives there. Never redeclare an IR type in another package.
2. **Analysis packages** (`spec`, `checker`, `render`, `extractor`, `conformance`, `testgen`) depend **only on `ir`**, never on each other. If two of them need the same helper, it moves into `ir` (pure types and pure utilities only).
3. **`cli` is the only orchestrator.** It wires packages together: spec → checker → extractor → conformance → testgen → render.
4. **`viewer`** may depend on `ir` and `render` (it reuses the Mermaid output).
5. **`runtime`** has zero internal dependencies and a minimal footprint, because it is loaded inside the user's test process.
6. **Tests may depend on other packages** (as `devDependencies`) for realistic inputs, e.g. extractor tests
   parse YAML with `@tsv/spec`, runtime tests type-check against `@tsv/ir`. `src/` never does.
7. No package reads the filesystem except `spec` (YAML loading), `extractor` (TypeScript project), `cli` (writes and runs generated tests), and `viewer` (server). `testgen` returns file contents; it never writes. Everything else is pure: data in, data out.

**API (M5):**
```ts
export interface ExtractOptions { projectRoot: string; tsconfig?: string }   // default <projectRoot>/tsconfig.json
export interface ExtractResult { spec: string; model?: BehaviorModel; findings: Finding[] }
export interface ExtractStats { files: number; writes: number; probes: number; durationMs: number }
export function extractAll(specs: BehaviorModel[], options: ExtractOptions): { results: ExtractResult[]; stats: ExtractStats };
```
One call per project: the Program is built once and every candidate write for every spec is probed up front
(X1's probe-first technique needs all probes before the first type query). Code models follow the conventions
documented on `ModelOrigin` in `packages/ir/src/model.ts`. The extractor reports `broken-link` (impl, client or
guard binding doesn't resolve) and `unanalyzable` (it can't tell); behavior mismatches are `conformance`'s job.

### 3.6 `@tsv/conformance`: spec model × code model → findings (M5)

**API:** `compare(spec: BehaviorModel, code: BehaviorModel): Finding[]` — pure, deterministic order. Rules
(spec transition `t`, code transitions linked to it via `sites.specTransition`):

| Condition | Category | Severity |
|---|---|---|
| Code transition with no `specTransition` | `undeclared-transition` | error |
| Linked code transition writes a state ≠ `t.to` (incl. states not in `entity.states`) | `undeclared-transition` | error |
| `t` has `impl` but no linked code transition writes `t.to` | `missing-transition` | error |
| `t` has no `impl` | — (info `unanalyzable`: "not linked to code") | info |
| Code `from` is `"*"` or `fromState.unconstrained` | `from-state-unconstrained` | error |
| Code `from` ⊋ `t.from` (extra states) | `from-state-mismatch` | error |
| Code `from` ⊊ `t.from` (code is stricter) | `from-state-mismatch` | warning |
| A guard in `t.requires` ∪ actor `requires` (for `t.by`) is not in code `requires` | `guard-not-dominating` | error |
| Code effect not declared on `t` | `undeclared-effect` | error |
| Effect declared on `t` not called by the code | `missing-effect` | error |
| `t.atomic` and not code `atomic` | `non-atomic` | error |

`specAt` = the spec transition's location; `codeAt` = the most specific code site (guard call, effect call,
write). Every finding has a one-line `hint`.

```
packages/conformance/src/
├─ index.ts           compare(spec, code) → Finding[]
├─ transitions.ts     undeclared / missing transitions, from-state mismatch
├─ guards.ts          requires vs. dominating guards
├─ effects.ts         declared vs. called effects
└─ atomicity.ts       atomic: true vs. extracted atomicity
```

## 4. Conventions

| Topic | Rule |
|---|---|
| Module format | ESM only (`"type": "module"`), `moduleResolution: "Bundler"`, extensionless relative imports |
| Workspace imports | `@tsv/<pkg>` only. Never use deep imports (`@tsv/ir/src/model`) |
| Package exports | Point at `./src/index.ts` during development. Publish-time build (tsup) comes later via `publishConfig` |
| Typecheck | `pnpm typecheck` = root `tsc --noEmit` over every package (TypeScript 7 native `tsc`) |
| Tests | vitest 5. Colocated `src/**/*.test.ts` for unit tests, `test/**` for fixture-driven tests. Golden outputs use `toMatchFileSnapshot` under `test/__golden__/` |
| Lint/format | Biome. `pnpm lint` must pass before every commit |
| Files | kebab-case, one concept per file. No `utils.ts` grab-bags. A helper lives next to its only user, or in `ir` if it's shared |
| Errors | Analysis code returns `Finding[]`. It throws only for programmer errors (which the CLI maps to exit 3) |
| Purity | Packages outside the FS list (§2 rule 7) take data and return data. No `process.*`, no console |
| Determinism | Stable ordering everywhere (sort by name) so golden files and PR diffs are stable |
| Node | Development runs on Node 26 LTS. `engines: ">=22.12"` (all supported LTS lines: 22, 24, 26); CI tests all three |

## 5. Branching, commits, and review

- `main` always passes `pnpm lint && pnpm typecheck && pnpm test`.
- **One branch per milestone slice**, named `m<N>/<package-or-topic>` (e.g. `m1/spec`, `m2/checker`), or `spike/x<N>-<topic>`.
- **Commits are small and self-contained**: each one builds and passes tests. They use Conventional Commit style: `feat(spec): parse rule expressions`, `test(checker): golden trace for refund race`, `chore: …`.
- Subagents work in **isolated git worktrees**, commit on their branch, and report back. The lead reviews the diff against this doc (ownership, dependency rules, conventions) and merges with `--no-ff`, so each milestone stays visible in history.
- A change to `ir` is a **contract change**: it must be called out in the branch report and reviewed first, because every package depends on it.

## 6. Dogfooding: `tsv` verifies itself

Building in TypeScript means `tsv` can check its own stateful parts with behavior files, once the extractor lands (M5):

| Component | Behavior file | Why it's stateful |
|---|---|---|
| Replay scheduler workers | `packages/runtime/src/scheduler.behavior.yaml` | `spawned → gated → running → done/failed`; gates must never release out of schedule order |
| Viewer playback | `packages/viewer/src/app/playback.behavior.yaml` | `idle → playing → paused → ended`; step cursor bounds |
| CLI run lifecycle | `packages/cli/src/run.behavior.yaml` | `loading → checking → extracting → reporting`; exit-code mapping |

The root `pnpm verify` script runs `tsv check` on the repo itself and is added to CI at M5.

## 9. Inputs to wave 3 (from the spikes and the demo app)

Full write-ups: [`spikes/x1-narrowing/README.md`](../spikes/x1-narrowing/README.md),
[`spikes/x2-gating/README.md`](../spikes/x2-gating/README.md),
[`examples/orders-app/variants/README.md`](../examples/orders-app/variants/README.md).

**X1 → extractor `TypeFacts`** (go):
- Technique: **probe-first injection**. Find candidate state writes syntactically, wrap each write `W` as
  `(ref.status, W)` in the in-memory project **before** the first type query, then read the probe's type.
  Public API only, 14/14 fixture cases, identical results on the TS 7 native checker.
- Two-phase API: `planNarrowing(requests)` (syntax only, before any type query) → `narrowedLiteralsAt(handle)`
  → `{ values: string[] | "*", declared, unconstrained, typeText }`, plus `toOriginalPosition()`.
- Walk raw `ts.Node`s, not ts-morph wrappers (wrapper walking dominated cost at scale).
- ts-morph 28 bundles TypeScript **6.0.2**. A TS 7 backend (`typescript/unstable/sync`) is possible later.
- Known gaps (report as `unconstrained`, not as bugs): `.includes` / `Set.has` guards, status copied to a
  local or destructured, aliased conditions on mutable fields. `string`/`any` fields → `unanalyzable`.
- Narrowing survives `await` and mutating calls, so the from-set is "value read", not "state at write".
  The atomicity check is required, not optional.

**X2 → runtime/testgen** (go):
- Scheduler: one worker runs at a time; a step "passes through" a gate; `sync` gates are model read/write
  points, `transparent` gates (transaction, effects) are passed automatically; precise divergence errors;
  `confirmed` / `confirmed-divergent` / `replay-disagrees` verdicts. 100/100 deterministic.
- `vi.mock` wiring: fakes as top-level consts, then a top-level `await import()` of the code under test.

**`CodeSites` must grow** (lead's `m5/ir-sites`, before the extractor starts). Replay and conformance need,
per read / write / effect site: client name + call path (the gate label, e.g. `db.orders.get`) and occurrence
index; the enclosing atomic scope (transaction / conditional update) and its site; how to invoke the impl
(entity-id parameter, actor parameter); the collection and key field; the client kind (repository / prisma /
drizzle).

**Demo app → extractor**:
- Scan **every** state write in the project, not only code reachable from `impl` (B1's `reopenOrder` has no `impl`).
- Guards appear before the transaction (`requireRole`) and inside it after the read (`requireOwner`).
- "Effect only if the transition happened" appears as: throw inside the transaction (refund), return
  `undefined` then `if (x === undefined) return` after commit (webhook), and data-dependent (`chargeId`).
- B2 is interprocedural (write + effect in a non-exported helper with one guarded and one unguarded call site).
- B4 keeps the transaction, so it must be `from-state-unconstrained`, not `non-atomic`.
