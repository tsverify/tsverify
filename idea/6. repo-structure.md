## 2. Dependency rules (enforced by review; a lint rule later)

```
                 ┌──────────────────────── cli ───────────────────────┐
                 │                                                    │
     spec   checker   render   extractor   conformance   testgen   viewer
       │       │        │          │            │           │        │
       └───────┴────────┴──────────┴─────┬──────┴───────────┘        │
                                         ▼                           │
                                        ir  ◀────────────────────────┘ (viewer → ir, render)

     runtime   (no internal deps: imported by *generated tests* in user projects)
```

1. **`ir` depends on nothing internal.** Every shared type lives there. Never redeclare an IR type in another package.
2. **Analysis packages** (`spec`, `checker`, `render`, `extractor`, `conformance`, `testgen`) depend **only on `ir`**, never on each other. If two of them need the same helper, it moves into `ir` (pure types and pure utilities only).
3. **`cli` is the only orchestrator.** It wires packages together: spec → checker → extractor → conformance → testgen → render.
4. **`viewer`** may depend on `ir` and `render` (it reuses the Mermaid output).
5. **`runtime`** has zero internal dependencies and a minimal footprint, because it is loaded inside the user's test process.
6. No package reads the filesystem except `spec` (YAML loading), `extractor` (TypeScript project), `testgen` (writes generated tests), `cli`, and `viewer` (server). Everything else is pure: data in, data out.

## 3. Packages, their modules, and what each owns

Conventions apply to every package (§4). Only the **public API** is exported from `src/index.ts`.

### 3.1 `@tsv/ir`: shared types and pure utilities (M0)

```
packages/ir/src/
├─ index.ts
├─ location.ts      SourceLocation
├─ model.ts         BehaviorModel, EntityDecl, Actor, Trust, Transition, EffectDecl,
│                   GuardRef, SymbolRef, CodeSites, Bindings, ClientBinding, GuardBinding
├─ expr.ts          Rule, RuleKind, Expr (rule AST), CmpOp
├─ trace.ts         Trace, TraceStep, TraceState, WorkerState, TraceAction
├─ finding.ts       Finding, FindingCategory, Severity, INPUT_ERROR_CATEGORIES
├─ builtins.ts      BUILTIN_PROPERTIES (ids + descriptions)
└─ refs.ts          parseSymbolRef / formatSymbolRef, parseGuardRef / formatGuardRef
```

**Owns:** the data model and its string formats (`file#symbol`, `role(admin)`). **Does not own:** parsing YAML, evaluating rules, or rendering.

### 3.2 `@tsv/spec`: YAML → validated `BehaviorModel` (M1)

```
packages/spec/src/
├─ index.ts           loadSpec(path), loadSpecs(glob), parseSpec(text, file), specJsonSchema()
├─ schema.ts          zod schema for *.behavior.yaml (the single source of the format)
├─ load.ts            yaml parse with positions (LineCounter), file discovery
├─ positions.ts       YAML node path → SourceLocation mapping
├─ normalize.ts       zod output → ir.BehaviorModel (defaults, from: string → string[])
├─ validate.ts        semantic checks zod can't express (unknown states/actors, duplicate names…)
├─ rules/
│  ├─ lexer.ts        rule expression tokens
│  └─ parser.ts       rule string → ir.Expr (with column-accurate errors)
└─ json-schema.ts     zod → JSON Schema (for yaml-language-server / agents)
test/fixtures/        valid + invalid specs
```

**Owns:** the YAML format, its JSON Schema, the rule-expression *syntax*, and `invalid-spec` findings. **Does not own:** `impl` link existence (that's `extractor`, which already loads the TypeScript project; reported as `broken-link`) or rule *evaluation* (`checker`).

### 3.3 `@tsv/checker`: explicit-state model checker (M2)

```
packages/checker/src/
├─ index.ts           check(model, options) → { findings, stats }
├─ encode.ts          compact state encoding (status, worker counts per phase, effect counts)
├─ semantics.ts       enabled actions + successors (atomic / read+write / duplicate delivery)
├─ explore.ts         BFS, visited set, parent pointers, bounds
├─ symmetry.ts        worker-count canonicalisation (symmetry reduction)
├─ eval.ts            ir.Expr evaluation against a decoded state
├─ properties/
│  ├─ invariants.ts   always / never rules + effect-multiplicity built-in
│  ├─ liveness.ts     eventually (AG EF) + no-stuck-states (reverse reachability)
│  ├─ reachability.ts reachable built-in
│  └─ lint.ts         untrusted-guarded, webhook-idempotent (structural, no exploration)
├─ trace.ts           parent chain → ir.Trace
└─ itf.ts             ir.Trace → ITF JSON (Quint/Apalache trace format)
bench/                throughput benchmark (doc 5 budget: ≥ 500k states/s)
```

**Owns:** behavioral semantics, built-in properties, counterexamples. It has to work the same on `origin: "spec"` and `origin: "code"` models.

### 3.4 `@tsv/render`: text and diagram outputs (M3)

```
packages/render/src/
├─ index.ts
├─ mermaid.ts         BehaviorModel → stateDiagram-v2 (escaping, stable ordering)
├─ matrix.ts          actor × transition permission matrix (Markdown + data form)
├─ summary.ts         deterministic plain-English summary
├─ diff.ts            BehaviorModel × BehaviorModel → BehaviorDiff (+ Markdown with highlighted Mermaid)  [M8]
├─ trace.ts           ir.Trace → step list text / Mermaid sequenceDiagram
└─ findings.ts        Finding[] → pretty terminal text (colours via an injected formatter)
```

**Owns:** every human-readable representation. The CLI and viewer never build strings for these themselves.

## 4. Conventions

| Topic | Rule |
|---|---|
| Module format | ESM only (`"type": "module"`), `moduleResolution: "Bundler"`, extensionless relative imports |
| Workspace imports | `@tsv/<pkg>` only. Never use deep imports (`@tsv/ir/src/model`) |
| Package exports | Point at `./src/index.ts` during development. Publish-time build (tsup) comes later via `publishConfig` |
| Typecheck | `pnpm typecheck` = root `tsc --noEmit` over every package (TypeScript 7 native `tsc`) |
| Tests | vitest 4. Colocated `src/**/*.test.ts` for unit tests, `test/**` for fixture-driven tests. Golden outputs use `toMatchFileSnapshot` under `test/__golden__/` |
| Lint/format | Biome. `pnpm lint` must pass before every commit |
| Files | kebab-case, one concept per file. No `utils.ts` grab-bags. A helper lives next to its only user, or in `ir` if it's shared |
| Errors | Analysis code returns `Finding[]`. It throws only for programmer errors (which the CLI maps to exit 3) |
| Purity | Packages outside the FS list (§2 rule 6) take data and return data. No `process.*`, no console |
| Determinism | Stable ordering everywhere (sort by name) so golden files and PR diffs are stable |
| Node | Development runs on Node 20.19. `engines: ">=20.19"` for now; revisit before release (Node 20 is EOL) |

## 5. Branching, commits, and review

- `main` always passes `pnpm lint && pnpm typecheck && pnpm test`.
- **One branch per milestone slice**, named `m<N>/<package-or-topic>` (e.g. `m1/spec`, `m2/checker`), or `spike/x<N>-<topic>`.
- **Commits are small and self-contained**: each one builds and passes tests. They use Conventional Commit style: `feat(spec): parse rule expressions`, `test(checker): golden trace for refund race`, `chore: …`.
- Subagents work in **isolated git worktrees**, commit on their branch, and report back. The lead reviews the diff against this doc (ownership, dependency rules, conventions) and merges with `--no-ff`, so each milestone stays visible in history.
- A change to `ir` is a **contract change**: it must be called out in the branch report and reviewed first, because every package depends on it.

## 6. Dogfooding: `tsv` verifies itself

Building in TypeScript means `tsv` can check its own stateful parts with behavior files, once the extractor lands (M5):

| Component | Behavior file | Why it's stateful |
|---|---|---|
| Replay scheduler workers | `packages/runtime/src/scheduler.behavior.yaml` | `spawned → gated → running → done/failed`; gates must never release out of schedule order |
| Viewer playback | `packages/viewer/src/app/playback.behavior.yaml` | `idle → playing → paused → ended`; step cursor bounds |
| CLI run lifecycle | `packages/cli/src/run.behavior.yaml` | `loading → checking → extracting → reporting`; exit-code mapping |

The root `pnpm verify` script runs `tsv check` on the repo itself and is added to CI at M5.
